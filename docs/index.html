Questions answered.

Speed, profile boundaries, encryption, and platforms.

How is Crown lighter than Chromium forks?

Instead of bundling another 150+ MB Chromium binary, Crown renders web pages using your operating system’s built-in WebView runtime (WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux, and Android WebView). Memory Saver also hibernates inactive background tabs across three configurable tiers so RAM stays low.

Are user profiles strictly isolated from one another?

Yes. Every non-default profile mounts its own separate native WebView data folder and its own encrypted local vault file. Switching profiles cleanly closes outgoing child tabs so cookies, storage, and active website sign-ins never leak across workspaces.

How does clearing browsing data and Incognito work?

Clearing history, cookies, or site data triggers native OS storage wiping directly against HTTP cookies, localStorage, IndexedDB, service workers, and disk caches, signing sites out cleanly. Incognito windows launch non-persistent RAM sessions that never save browsing history, cookies, or frequent shortcuts.

How are saved vault passwords encrypted on disk?

Saved secrets are encrypted with 256-bit AES-GCM using authenticated context data and zeroized memory buffers in Rust. Master keys are sealed with Windows DPAPI on Windows and strict owner-only 0o600 permissions on Unix, with OS Keychain and Secret Service support planned next.

Why is the Android APK marked Coming Soon?

Desktop v1.0.0 installers (Windows, macOS, Linux) share the primary tested desktop shell and ship first. You can already build Android from source with npm run build:android, while prebuilt APKs await full device hardware verification before release.
